# 陪跑（fitloop）

一个每天陪你减脂的小工具。你随口说吃了什么、练了什么，它记下来、算额度、给建议；晚上结算，第二天接着来。

不是聊天机器人套壳——**能算的归代码，要判断的归模型**。

## 它是怎么分工的

| 层 | 谁 | 干什么 |
|---|---|---|
| 语义 | 模型 | 把你的一句话拆成记录（几件事、什么类型） |
| 口径 | 代码 | 热量区间、分档、蛋白缺口、趋势、解锁 |
| 表达 | 模型 | 把数字说成人话 |

**判档、拦截、门槛全部是代码，模型没有投票权。** 这是刻意的：模型会抖，但"你今天吃 750 卡"这个判断必须每次都一样。

## 已经能做的

- 一句话拆多件事：「早上包子豆浆，中午没吃，晚上牛肉面」→ 三条，含"没吃"这种阴性记录
- 改记录：说「那是去皮的」，它会改掉那条重算，不是再记一条
- 说错体重会拦：「今天称重15kg」→ 不收，提示是不是打错了
- 睡眠不足自动降训练：「睡了4小时」→ 今天不安排训练
- 受伤/生病直接停，转就医，不再给任何计划
- 每天一次自动压缩：隔天把前一天压成一行硬事实（热量 / 条数 / 蛋白 / 钠 / 睡眠 / 档位）
- 原始条目按天归档，能回查：「10月18日吃了什么」→ 列出那天的明细；太老只剩合计
- 训练记录进 state：负荷算得出来，「吃少 + 练多」这条组合规则**真的会触发**
- 自由餐解锁规则（开局 14 天不排、最密每 3 天一次）：函数与单测已就位，**尚未接进交互流程**

## 设计稿与当前实现的差异

`DESIGN.md`（v1.1）和 `GRAPH.md`（v1.2）都是**设计稿**，不是当前实现。跑起来的版本是简化版，差异如下：

| 项 | 设计稿 | 当前实现 |
|---|---|---|
| 图 | 7 类事件 + `day_start` / `day_end` / `goal_check` + overrides | **5 个节点**：`wait` / `parse` / `clarify` / `handle` / `handoff` |
| 打断 | 1 个 `wait_event` | **2 个**：`wait`（等输入）+ `clarify`（追问份量） |
| 事件路由 | LLM 用 `Command(goto=)` 选边 | **代码判定**，模型只给 `needs_clarify` 标志 |
| 医疗 | L0–L3 四级分级 | **命中即停**，不分级，话术由代码输出 |
| 负荷 | `load_level` / `escalate` 参与判档 | 函数与单测已就位，**未接入**：train 事件只回一句占位 |
| 评测 | 60 条混淆矩阵 + 14 天使用 | 19 条解析评测集；`eval/run_parse.py` 缺 `import os`，当前跑不起来，无分数 |

判断口径：**已实现 ≠ 已生效**。上表右列是代码里真实存在并会被调用的路径。

## 怎么跑

```bash
pip install -r requirements.txt
echo "FITLOOP_API_KEY=sk-你的key" > .env
python server.py          # 端口默认 8791，可用 FITLOOP_PORT 改
# 打开 http://127.0.0.1:8791
```

第一次打开会让你填身高体重年龄，然后给出建议目标。

## 测试

```bash
python test_core.py      # 95 条断言，不调模型
python test_plan_rules.py test_resolve.py test_trend.py   # 24 + 13 + 11 条，四套合计 143 条
python check_ui.py       # 页面自检：语法 + 元素 + 字段对齐
python eval/run_parse.py # 19 条解析评测，会调模型（当前缺 import os，需先修）
```

## 素材

- `core.py` 纯计算：分档、区间合成、睡眠、医疗停止、自由餐、趋势
- `graph_app.py` LangGraph：等待 → 解析 → 追问 → 处理
- `app.py` 模型调用与记录
- `server.py` / `static/index.html` 网页界面
